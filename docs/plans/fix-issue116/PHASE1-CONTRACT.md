## 术语与坐标口径

以下口径只用于统一验收语言，不指任何实现：

- **屏显区域（client 坐标，唯一验收比较区间）**：用户在 iPad 上实际能看到的区域，几何一律在 **client 坐标**下读取，不把任何 offset 加回 rect（冻结文档 §4：`vv.offsetTop` 不参与 raw 算式；`5268869` 源码注释：covered/uncovered boundary lives at `vv.height` in client coordinates）。可测口径：**屏显区域 = `[0, vv.height]`**，键盘顶边是其下边界 `y = vv.height`——**未发生系统 pan 与发生 pan 时该区间本身都不变**。"某元素位于屏显区域内" = 该元素 client rect 与 `[0, vv.height]` 比较成立；持续 pan 时外壳 / 宿主 client rect 随 pan 平移，越出区间即出屏事实，按 F17 判定。
  - **可见窗口（布局坐标，另一坐标下的同一窗口，另句描述）**：布局坐标下可视窗口位于 **`[vv.offsetTop, vv.offsetTop + vv.height]`**，只描述同一个窗口在布局坐标中的落点。屏显区域与可见窗口是**同一个窗口的两种坐标描述**：**禁止混用两种坐标做同一比较、禁止相加、禁止把 `vv.offsetTop` 加进 rect 或 raw 算式**（PLAN §3、冻结文档 §4）。
  - **测量 ≠ 补偿**：**诊断测量**读取 `vv.offsetTop`（记录 pan 事实、描述上述可见窗口）**不属于** PLAN §3 禁止的"把 `vv.offsetTop` 简单加入现有 raw 算式"——§3 禁止的是把 `offsetTop` 写进补偿算式形成重复补偿，不禁止读取它做诊断与事实记录。
  - **诊断浮层自身换算的窄豁免**：为把诊断面板**自身**的 fixed 盒子放进屏显区域，其自身 inset 允许做 layout ↔ client 换算并携带 `vv.offsetTop`（横向对应 `vv.offsetLeft`）；这只豁免工具自身落位，**同一换算不得进入产品 raw、`occlusion`、终端 / 外壳或其他产品几何的写入**，验收比较仍一律使用 client 坐标 `[0, vv.height]`（横向 `[0, vv.width]`）。本句不削弱“测量 ≠ 补偿”，也不授权任何产品代码改动。
  - **持续 pan 期间**（`vv.offsetTop ≠ 0` 持续存在）：GI-2 / GI-3 一律按 client 坐标 `[0, vv.height]` 区间评估，宿主 / 外壳 rect 越出该区间即违反事实；持续违反即按 F17 停止实现并回到 D1，不得改用布局坐标区间比较来"救回"判定，也不得为"看起来没出屏"改写比较口径。
- **可用视口（终端）**：前台 PTY 终端实际可呈现内容的区域；"完整可见"只指当前可用视口及其输入区域，不含一次性显示全部 scrollback（核心原则 §2.1）。
- **输入行**：用户当前正在输入的那一行所对应的终端区域（真机以聚焦行 rect / xterm 行几何观测）。**最后一行**：终端当前输出的最后一行所在区域（真机以 `xtermRows` 末行 rect 观测）。二者是**可分别判定的两个量**，可以不在同一行：多行 / 续行输入、向上翻看历史输出、补全提示或 IME 候选窗在输入行下方占位等场景下，二者位置与可见性都可能不同；验收须分别记录，不得以"最后一行可见"代替"输入行可见"，反之亦然。原"终端输入区"一词同时指二者，自本文起**不再作为单一判定量**使用（只作口语统称）。
- **软键盘避让会话（活动避让会话）**：冻结文档 §5 键盘会话状态机处于 `terminalAvoidanceActive` 的期间；**只有该区间触发键盘几何义务**（义务区间 = 会话区间）。口径（冻结 §5 + `5268869` 源码 + 现役 p9 `verify-sop.mjs`）：`raw = max(0, clientHeight − vv.height)`；**进入** = 非缩放 + 可编辑焦点 + `raw > 1` + 无恢复锁，且 `raw ≥ 布局高 × 25%`；**恢复后重入** = 恢复锁期间需 `raw ≥ 布局高 × 50%`，或冻结基线认可的**新终端点击（`click`，非 `touchstart`）/ 新 `focusin` / 窗口几何变化**解锁后再按进入线判定；**会话内** `occlusion = raw` 全额，**25% / 50% 不是对已活动会话持续应用的过滤地板**；**退出** = 同一窗口几何下 raw 回落 > 1px **立即退出并进恢复锁**，或 `raw ≤ 1` / 焦点不再是可编辑宿主 / 缩放态——**三种退出条件在会话退出前为 active 时均置恢复锁**（源码 3767–3771；`verify-sop.mjs` 184–186 与 zoom 分支 167–172）；冻结 §5.4 只显式描述了"同几何回落退出"这一条置锁，另两条置锁取自 §5.6 退出条件与上述源码 / 重放器口径；**几何宽容** = 已有会话遇窗口几何变化按冻结 §5.7 保留一次 settle 宽容（只消费一次）。25% / 50% 只是进入 / 重入门槛。
- **IME 组合态 ≠ 避让会话持续声明**：中文 / 日文等输入法尚未上屏的组合窗口期间是**同一个逻辑输入过程**，组合窗口占位不得被判为"键盘重新弹出"，也不得被当作除键盘顶边变化之外的新遮挡来源；但**几何避让会话是否 active 仍按上述冻结 §5 状态机的当帧条件判定**——"IME 属同一逻辑输入过程"不能推定避让会话始终 active，不得用 IME 表述覆盖冻结退出规则（`raw ≤ 1` / 失焦 / 缩放退出、同几何回落退出）。
- **归属（所有权）**：由当前焦点决定的"谁负责输入可见性"，不是进程锁、不是标志位、不是 pan 开关。
- **归属状态 vs 义务生效条件**（两个不同概念，必须分开表述）：**归属状态**（HO-1 / HO-2 / HO-3 / HO-4）只由当前焦点落点决定，回答"谁负责输入可见性"；**义务生效条件**回答"某条义务此刻是否适用"。键盘几何相关的义务（让位、落在键盘之上、终端可用视口完整）以"存在**活动软键盘避让会话**"（术语章）为前提，**义务区间 = 会话区间**：会话未处于 active 时该义务**休眠**——既不产生 FAIL，也**不改变归属状态**；禁止性义务（不额外避让、不抢回、不叠加补偿、不清空所有权）在任意归属下持续生效。因此"键盘收起 / 会话退出"只切换义务前提，**不是归属的合取条件**，也不视为退出归属（见 HO-2 与 C 表 F18）。
- **键盘遮挡 / pan / zoom**：三件相关但独立的问题——键盘覆盖了多少屏显区域 / Safari 为让聚焦输入可见而移动可视窗口 / 页面缩放比例变化；不得用一项全局补偿同时处理（核心原则 §1）。
- **让位**：终端相关盒子把自己从键盘遮挡中挪开的几何变化。本契约只在 HO-2 讨论让位是否发生及其目标；现状基线：**活动避让会话内** `occlusion = raw` 全额让位（冻结 §5.3），非会话期 `occlusion = 0`、满高被浮窗覆盖是预期（冻结 §5.4 / §5.6）。0.15 比值地板是 v3.1 历史 SOP 的说法，已废除，不属现状。
- **前台实例**：当前被展示、其终端宿主可交互的 PTY 实例。隐藏 / 非活动实例不是前台实例。
- **稳定帧 / 过渡帧**：稳定帧 = 现役 p9 `evidence/verify-sop.mjs` 的 reason 口径：`manual` / `settle` / `periodic` / `keyboard-hint` / `magic-hint`，作为判定载体；`resize` / `scroll` 过渡帧只作旁证（历史 A0-SOP 第 6 / 8 项有同名分帧口径，属历史 SOP 表述）。

## B. 逻辑输入所有权（四态定义）

判定依据**只有一个**：当前焦点属于谁。**"屏幕上是否显示终端"永远不是判定依据**（核心原则 §3 末段：判断依据不是"屏幕上是否显示终端"，而是"当前焦点是否属于前台 PTY 的终端输入宿主"；该段并举例——终端仍在背景中但用户正在重命名实例时，应归入普通 Web 输入，而不是继续持有终端输入所有权）。

逻辑消歧顺序（顺序是逻辑判定顺序，不是实现指令，不得映射为某个变量或状态机）：

`焦点落在前台 PTY 终端输入宿主？ → 是：前台 PTY（HO-2）`；否则 `焦点落在非前台 / 隐藏的终端宿主？ → 是：无归属（HO-1，该宿主无取得资格）`；否则 `焦点落在本页其他非终端可编辑宿主？ → 是：普通 Web 输入（HO-3）`；否则 `焦点已离开父文档、落在 iframe 内部的可编辑宿主？ → iframe 输入（HO-4）`；否则 `无归属（HO-1）`。

消歧补充（与上面同一口径，不引入新条件）：

- **是否存在活动避让会话不是归属的合取条件**：四态的成立都只看焦点落点，不看键盘此刻是否打开、不看冻结 §5 状态机是否 active。键盘开合 / 会话开合只切换"键盘几何义务"的前提（义务区间 = 会话区间），不改判归属（核心原则 §3 第 4 行对"无编辑焦点或无确认的软键盘输入会话"写的是**沿用既定状态分类**，不是"一律改判无归属"；术语见"归属状态 vs 义务生效条件"与"软键盘避让会话"）。
- **iframe 文档内的非可编辑焦点**（iframe 内按钮、静态文本、空白区）不成立 HO-4，落入 **HO-1（无归属）**；父页面**仍不干预 iframe 内部**，只是不承担终端避让（与 HO-4 进入条件一致：HO-4 只在 iframe 内**可编辑**宿主持焦时成立）。
- **焦点落在隐藏 / 非活动实例的终端宿主内**：该宿主没有取得归属的资格（核心原则 §5 末段），落入 **HO-1**；本态不因其是"终端宿主"而判 HO-2 或 HO-3。

**终端输入宿主**是逻辑角色名：真机上它对应哪一类 DOM 宿主（例如 xterm 的 helper textarea）由 Phase 2 实测确认（PLAN Phase 2 任务 3），本文不预设、不点名实现。

**Phase 2 探针命名不升格为产品契约**：`937d91f` 探针的 `activeInput.role` 及 xterm / helper class 启发式只是实测先行的诊断命名与归属线索，不是 HO-1..HO-4 之外的验收枚举，也不得单独充当“真实终端输入宿主”的权威证明；服务端当前对 `role` 只校验小写字母 / 连字符形状，并未登记一份契约角色枚举。产品显式宿主标记（例如 `data-input-host="pty"`）只能列为 Phase 3 候选改动，须有真机证据并另行取得产品实现授权；未经授权不得把启发式命名当作验收权威。

### HO-1 无归属

- **进入条件**：无可编辑焦点；或焦点在按钮、tab、标签、静态文本、滚动容器等非编辑宿主上；或**焦点已不在任何可编辑宿主上（此前存在过编辑焦点）**；或焦点落在无取得资格的隐藏 / 非活动终端宿主内（核心原则 §5 末段）；或焦点落在 iframe 文档内的非可编辑元素上（见 B 章消歧补充）。
- **判定依据**：焦点既不属于前台 PTY 终端输入宿主，也不属于本页其他可编辑宿主，也不在 iframe 内的可编辑宿主上（隐藏 / 非活动终端宿主与 iframe 内的非可编辑焦点都落在本态内）。键盘此刻是否打开**不改变**本态是否成立，只使键盘相关义务的前提不成立。
- **退出条件**：`focusin` 落到可识别类别的可编辑宿主。
- **该状态下的义务**：不额外避让；不主动控制系统 pan；不得为"看起来更稳"主动改写终端或外壳几何；不得抢回原点（PLAN §3）。此前遗留的终端几何结果只作为等待重判的历史值，**不得**在重新进入 PTY 态时被当作前提沿用（见 HO-4 与 GI-8）。

### HO-2 前台 PTY 输入

- **进入条件**：焦点落在**前台 PTY 实例**的终端输入宿主上。"前台"= 该实例当前被展示且其终端宿主可交互；隐藏或非活动实例不满足（核心原则 §5 末段）。
- **判定依据**：当前焦点属于该前台 PTY 的终端输入宿主本身，而不是"终端可见"或"存在软键盘"。**活动避让会话不是进入或留在本态的合取条件**：焦点在本宿主上时，即使软键盘尚未弹出、已被收起或状态机处于恢复锁，归属仍是 HO-2。
- **退出条件**：焦点离开该宿主——切到本页 Web 输入、切到 iframe 内的可编辑宿主、失焦（焦点落到父文档非编辑元素）、前台实例变化、宿主被隐藏、进入后台，任一成立即退出。**键盘收起 / 避让会话退出不在退出条件之内**（义务前提切换见 F18）。
- **该状态下的义务**（R1），分两组、不得互相抵充：
  - **常驻义务（归属本身携带，与键盘无关）**：只调整终端相关几何；不重新钉短整个应用外壳；不抢回原点；不以 Safari 把终端主体 pan 出屏显区域作为最终体验；fit / resize / ack 最终一致；焦点未变而几何变化时按当时事实重判。
  - **键盘几何义务（前提：存在活动软键盘避让会话；义务区间 = 会话区间）**：会话内终端可用视口、输入行与最后一行、quick-keys、Transport 应位于屏显区域 `[0, vv.height]` 内，并按 `occlusion = raw` 全额让位（冻结 §4 写入集合、§5.3）。**前提不成立（终端持焦但状态机非 active——未进入、恢复锁中或已退出）时本组义务休眠**：`occlusion = 0`、终端满高被浅浮窗覆盖是冻结 §5 的预期，不得因键盘收起而释放终端所有权，也不得沿用键盘收起帧的历史几何作为当前判据；再次生效必须按冻结 §5 重新判定（恢复后重入需 `raw ≥ 布局高 × 50%` 或新点击 / 新 `focusin` / 窗口几何变化解锁；见术语章与 C 表 F18）。

### HO-3 普通 Web 输入

- **进入条件**：焦点落在本页非终端可编辑宿主：新建 / 重命名 worktree、新建 / 重命名实例、设置与其他本页表单、quick-keys **粘贴 textarea**、其他 `input` / `textarea` / `contenteditable`（核心原则 §4）。
- **判定依据**：焦点元素在本页文档内，且不属于**任何**终端输入宿主（含前台与非前台 / 隐藏的终端宿主）；焦点落在隐藏或非活动终端宿主内时不成立本态，按 HO-1 处理（见 B.5）。终端即使仍在背景完整可见，本态成立即归属为 Safari。
- **退出条件**：焦点离开该输入，或焦点重新落到前台 PTY 终端输入宿主。
- **该状态下的义务**（R2）：可见性交由 Safari 按实际输入位置做最小 pan；**不因该聚焦触发任何 PTY 避让**；不阻止系统 pan；不把应用补偿叠加在 Safari pan 之上。
- **注意（可达性与归属是两个命题）**：quick-keys 的**面板与入口按钮本身不是输入宿主**。面板可见但焦点仍在终端时仍是 HO-2；焦点进入粘贴 textarea 时输入归属转为 HO-3，而"面板本身必须可达"仍作为独立的可达性要求保留（PLAN §6 明确二者"分别成立"）。本契约只禁止"因该 textarea 聚焦而额外施加终端避让 / 双重补偿"。

### HO-4 iframe 输入

- **进入条件**：**可编辑**焦点位于 opencode / reasonix / dsh 等 iframe 内部文档。iframe 文档内的**非可编辑**焦点（iframe 内按钮、静态文本、空白区）不成立本态，按 HO-1（无归属）处理，但父页面**仍不干预 iframe 内部**（与 HO-1 义务一致）。
- **判定依据**：逻辑上表现为"可编辑焦点不在父文档内"。父页面**不新增跨 iframe 光标/位置协议**，不得要求 iframe 上报内部状态，也不得反向猜测 iframe 内部布局（R3、核心原则 §2.3 / §6）。
- **退出条件**：焦点回到父文档，并重新按 HO-1 / HO-2 / HO-3 识别。
- **该状态下的义务**：父页面无干预；不施加终端避让；不阻止 iframe 与 Safari 的原生协作。
- **推论**：父页面观察到"父文档焦点消失"时**不得**默认继续持有或撤销终端所有权，只能得出"焦点不再属于前台 PTY 终端输入宿主"，从而按 **HO-1 / HO-4 共有的禁止性义务**处理（不新增补偿、不猜内部落点）。

**交接判定纪律**（对全表的横向约束，对应 PLAN Phase 3 任务 3 的行为测试面）：

- 连续事件与顺序：`focusin` / `focusout` 交错、快速来回切换、同一 tick 内多次归属变化，最终归属必须以**最后一次的焦点落点**为准。
- 旧焦点残留：前一个归属的判据、让位与行数结果在变更后不得继续生效（F1–F20 各行的"必须清理"就是这个要求的分场景形式）。
- 键盘已打开时的交接：归属变化不改变键盘状态，必须按"键盘仍在"的当前几何重新判定，不得把"键盘曾收起过"或"曾打开过"当作前提。
- **键盘开合 / 会话开合不改判归属**：键盘弹出 / 收起与冻结 §5 避让会话的开合只切换键盘几何义务的前提（义务区间 = 会话区间），不是归属的合取条件；终端持焦而键盘收起、状态机进恢复锁仍是 HO-2（F18），焦点未变时不得因键盘 / 会话事件把归属降为 HO-1。
- 无法判定归属时不猜：落到 HO-1 的禁止性义务（不新增补偿），并按 F 节口径记 INCONCLUSIVE。

## D. 几何不变量（目标契约 vs 当前冻结基线）

每条含【目标契约】（待实现、待真机验证的 MUST）与【当前冻结基线】（对现行冻结基线的引用描述：[IPADOS-UI-COMPATIBILITY.md](../../IPADOS-UI-COMPATIBILITY.md) §3/§4/§5/§8 + `5268869` 源码 + 现役 p9 `verify-sop.mjs`）。**基线成立不等于目标达成**。

### GI-1 应用外壳 `#app`

- **目标**：`#app` 不因终端输入所有权被钉成 `visualViewport.height` 高度，也不作为整体被移出屏显区域；应用不重钉、不抢回、不反向 transform（PLAN §3）。
- **基线**：满高壳 + `position: fixed` + 根不可滚，`#app` inline height 恒空（冻结文档 §2.1 根 `overflow: clip`、§2.2 满高壳不再随 `vv.height` 改变、§3 铺底与真实底边）。**但**C 会话存在持续系统 pan：`vv.offsetTop=403`、`app.top=-403`、120 个稳定帧，手动 Capture `seq 136 / 266 / 310 / 549` 四次同值——"外壳不被整体移动"这一目标**当前未达成**（外壳 client rect 越出 `[0, vv.height]`），其解决路径归 D1（未签署），本文不指定机制。

### GI-2 PTY 可用视口（终端宿主）

- **目标**：处于 HO-2 且处于**活动软键盘避让会话**内时，前台 PTY 的终端可用视口完整位于屏显区域内；调整只作用于终端相关几何，不缩短外壳；"完整"指当前可用视口及输入区域（输入行与最后一行分别判定，见术语章），不含一次性显示全部 scrollback（核心原则 §2.1）。屏显区域按术语章取 client 坐标 `[0, vv.height]`（布局坐标下的可见窗口 `[vv.offsetTop, vv.offsetTop + vv.height]` 是同一窗口的另一坐标描述，另句记录、禁止混用）；**持续 pan 期间本项按该区间评估，宿主 / 外壳 rect 越出区间即违反事实，持续违反即按 F17 停止并回到 D1**。
- **基线**：`raw = max(0, clientHeight − vv.height)`，`vv.offsetTop` 不参与算式（冻结文档 §4 唯一写入集合：宿主 `bottom = occlusion`、控制列 `20 + occlusion`、Transport `occlusion`）；`occlusion` 由冻结 §5 键盘会话状态机决定——非缩放 + 可编辑焦点 + `raw > 1` + 无恢复锁且 `raw ≥ 布局高 × 25%` 进入；**会话内 `occlusion = raw` 全额（25% / 50% 不是持续过滤地板）**；同几何 raw 回落 > 1px 立即退出进恢复锁；恢复后需 `raw ≥ 布局高 × 50%` 或新点击 / 新 `focusin` / 窗口几何变化解锁；`raw ≤ 1` / 失焦 / 缩放退出为 0（**非活动会话期被浅浮窗覆盖是冻结 §5 的预期设计行为**）。现役 p9 `verify-sop.mjs` 以 `KEYBOARD_ENTRY_RATIO = 0.25` / `KEYBOARD_REENTRY_RATIO = 0.50` 逐帧重放该状态机（**该重放不建模 `click` 解锁与 500ms 自检 tick，保真度边界见头部限定与下条**）。v3.1 的 0.15 比值地板是历史规则（已被 `4def4d6` / `f4a6839` 废除），不是本基线。**C 会话中出现 PTY 宿主底边 −103**（`vv.offsetTop=403`；同一形态见于 `settle` / `periodic` 稳定帧 `seq 38–42`、`seq 85–87` 等），终端可整体离开屏显区域 → 目标**当前未达成**。
- **重放保真度缺口（已登记集群，关联头部限定）**：C 会话 `seq 373–377`（`resize` / `settle` / `periodic`）布局高 1108、`vv.height=768`、`raw=340`（= 布局高 × 30.7%）、reported `occlusion = 340`，而 p9 重放 owed `0`——其前帧 `seq 370–372` `raw=0` 已按冻结 §5.4 / §5.6 退出并置恢复锁（源码 3767–3771），重放侧到 `seq 373` 只认 `reason === "focusin"`（`verify-sop.mjs` 178）与几何变化（同文件 182）两条解锁，而该解锁变化按冻结口径只看布局高与 VV 宽度（源码 3761–3765：`1108 × 834` 全程未变，`seq 373` 变的只是 `vv.height`）故不触发解锁，且 `raw=340 < 1108 × 50% = 554` 故不重入；**可能成因**：该段存在未被探针捕获的 `click` 解锁（源码 3880–3882；C raw 中 `click` 帧数为 0）→ 产品按冻结 §5.5 正确解锁并重入，**亦不能排除 §5.5 偏离**。本集群按头部限定记 **INCONCLUSIVE**，列为 **Phase 2 补证项**：`937d91f` 的 `unlockTrace` 已能留下 click / touchstart、tick 与同瞬间几何，但冻结 `makeKeyboardSessionJudge` 不消费它，当前也没有任何获授权的读者 / 判读流程；因此它目前只是**可采证 groundwork**，不得以 `counts.click > 0`、单条 entry 或 tick 差直接宣称解锁成立或本集群闭合。在该读者与判读流程获独立授权前，本集群持续 **INCONCLUSIVE**；未来授权也只能把该痕迹与完整连续会话、测量字段共同判读，不能凭 reported 值单独判 PASS；本集群属"提前让位 / 重入线分歧"，**不适用** GI-2 / GI-3 / GI-4 / GI-5 共用三态滞后规则（见该节"适用范围"）。**登记完备性**：按 `verify-sop.mjs` 163–202 同口径对 C 会话全量独立复算，重放与 reported 的分歧只有两处——`seq 373–377`（reported > owed，即本集群）与 `seq 573`（reported < owed，即 GI-3"事实补记"的 applied 滞后帧，不属本类）；C 会话内无第三处未登记分歧。

### GI-3 终端输入行与最后一行

- **目标**：**活动避让会话**期间，终端**输入行**与**最后一行**位于键盘之上可见（client 坐标 `rect.bottom ≤ vv.height + 1`），不被键盘压住；二者是分别判定的两个量（术语章），须各自成立、不得互相代替。
- **基线**：现役 p9 `verify-sop.mjs` **只在避让会话的让位稳定帧**判 `xtermRows.bottom ≤ vv.height + 1`；非会话期（owed = 0）终端满高、`xtermRows.bottom` 越出 `vv.height` 是冻结 §5 的预期，不是 FAIL。pan 帧下（GI-1 / GI-2 所述）该目标**未达成**。行数减少本身是产品可接受后果，但不等于"目标已实现"。
- **事实补记（滞后实例）**：C 会话 `seq 573` 是 `periodic` **稳定帧**，`vv.height` 已由 679.5 变为 320，而 `occlusion` 仍为 `0`、`xtermRows.bottom` 仍为 `720`（即 applier 滞后一帧）；紧接的 `seq 574`（`resize` 过渡帧）applied 尺寸已更新为 `occlusion=428`、`xtermRows.bottom=295`，下一个稳定帧 `seq 575`（`settle`）保持正确。此类候选滞后帧的判据适用**GI-2 / GI-3 / GI-4 / GI-5 共用三态规则**（见 GI-5 后的专节；本契约新目标口径）；该稳定帧在现行 p9 重放口径下 owed `occlusion = 428` 而 reported `0`，按现行口径属已记录的不一致事实——本文不豁免、也不宣称其已通过冻结验收。

### GI-4 quick-keys（入口 / 面板 / 控制列）

- **目标**：面板打开时其内容在盒内可达并可滚；入口按钮不因键盘跳动；**活动避让会话**期间 quick-keys 整体位于屏显区域 `[0, vv.height]` 内；**窗口 / 方向变化后（F12、F20）面板仍须在盒内可达**（与 F12 / F20 联动：不得沿用旧方向或旧窗口的列高与面板高度判据）；面板可达性与输入归属（HO-3）是两个独立命题。
- **基线**：控制列 `bottom = 20 + occlusion`、`top:20px` 永不写、面板 `max-height:100%` 随列收缩并内部滚动（冻结文档 §3.3 终端控制列；写入集合见 §4）；C 会话 `seq 88–99` 连续 12 帧在该场景判 **PASS**——只认证几何与命中，不替代用户目测，也不覆盖该会话其余帧（该会话另有 8 个序列缺口）。

### GI-5 Transport `#status-bar`

- **目标**：传输状态条在**活动避让会话**期间可见于键盘之上（client 坐标 `rect.bottom ≤ vv.height + 1`），且与 quick-keys 控制列底边不同（不得重叠埋没）。
- **基线**：冻结文档 §3.3 Transport——`#status-bar` `position: fixed`、无避让时 `bottom: 0` 贴物理视口底、避让时只写自己的 `bottom = occlusion`；现役 p9 `verify-sop.mjs` **只在让位稳定帧**要求真实底 `≤ vv.height + 1`；非活动会话 / 恢复退出帧越界被覆盖为冻结 §5 预期，不是缺陷。真机（safe-area≈20）下状态条比控制列底更靠下一截是**预期结果**（§3.3：`fixed` 不再继承 `#workspace` 的 safe-area 内缩）。

### GI-2 / GI-3 / GI-4 / GI-5 共用口径：候选滞后帧三态规则（本契约新目标口径）

- **适用范围（只限"applied 值滞后"类）**：VV 几何已变而 GI-2 / GI-3 / GI-4 / GI-5 的对应 applied 值（`occlusion`、宿主 / 控制列 / Transport 底边、`xtermRows`）尚未更新的**候选滞后帧**，一律按本规则处置：**候选滞后帧暂记过渡帧——不计 PASS 也不计 FAIL**；**下一稳定帧全部相关字段都已更新** → 该滞后闭合；下一稳定帧仍未更新 → 滞后链**FAIL**。本规则**只适用于"applied 值滞后"类差异**（产品落后于重放）；**不适用于"提前让位 / 重入线分歧"类差异**（reported > 重放 owed，如 GI-2 基线段登记的 C 会话 `seq 373–377`）——后者按头部保真度限定处置：缺 §5.5 解锁事件证据记 INCONCLUSIVE，不得借本规则转记过渡帧或闭合。
- **INCONCLUSIVE 条件**：无下一稳定帧可对照、其间有 seq 缺口、或判定所需字段缺失 → **INCONCLUSIVE**，不得默认闭合也不得默认通过。
- **不豁免项**：外壳高度（GI-1）、根可滚性（GI-6）、持续 pan 与终端出屏（F17、GI-7 适用性段）、归属判定（B 章）与证据完整性（F 章通用规则）永不因本规则获得豁免——本规则只处置顺序性滞后，不处置违反事实。
- **口径属性**：这是**本契约的新目标口径**，不改变现役冻结验收（`5268869` + p9 `verify-sop.mjs`）；**不得宣称 `seq 573` 已通过冻结验收**——按现行 p9 状态机重放，该稳定帧 reported `occlusion = 0` 与 owed `428` 不一致，属现行口径下已记录的事实。
- **证据强度**：本规则目前仅基于 **1 个观测实例**（`seq 573–575`）；是否升格为固定验收口径，须先由 Phase 2 复核其在真机数据中的出现频率后再定。

### GI-6 pan 与可滚范围

- **目标**：系统 pan 不作为终端体验的基础；根无可滚范围；应用不通过 `scrollTo(0,0)`、反复写根 `scrollTop` 或反向 transform 抢回页面（PLAN §3）；持续非预期 pan 或终端出屏即停止并回到 D1（PLAN Phase 4 门禁）。
- **基线**：结构层面已成立——583 帧全部 `rootScrollHeight == clientHeight`、`#app` inline height 始终为空、结构仍是 clip + fixed（VALIDATION"新反馈"节）。**但**结构不可滚不排除 Safari 自身 pan：同上，`vv.offsetTop=403` 持续存在。此张力的解决权在 D1（暂缓）；本文只并列"目标"与"禁止手段"，不授权任何试修。

### GI-7 最终 PTY rows / cols 与 ack

- **目标**：fit / resize / ack 最终一致——**避让会话**稳定或退出（关闭 / `raw ≤ 1` / 失焦 / 缩放 / 同几何回落恢复）后的最终 rows/cols 与最终可用视口一致，收敛为单一 applied 尺寸；旧 ack 不得回刷已确认尺寸；最终尺寸去重与断开清理保持（或有等价回归证明）。
- **基线**：现有实现保留 trailing resize、最终尺寸去重、断开清理与旧 ack 不回刷（冻结文档 §7 PTY refit 与最终尺寸同步；PLAN Phase 4 任务 3 的现状表述）。`seq 573 → 574` 存在一帧"VV 已变、applier 尚未更新"的周期/resize 顺序差，下一帧即正确；此类帧的滞后判定适用 **GI-2 / GI-3 / GI-4 / GI-5 共用三态规则**（新目标口径；本文**不宣称 `seq 573` 已通过冻结验收**，见该节"口径属性"）。**针对本契约的键盘期间 refit 最终一致性尚未真机复测 → 未验证。**
- **持续 pan 期间的适用性**：持续 pan（`vv.offsetTop ≠ 0` 持续存在、终端出屏）期间**本项不适用**——不得以"rows/cols 最终会一致"评审判定，必须先按 F17 判 **FAIL** 并停止实现回到 D1（持续 pan 与终端出屏属停止型 FAIL，见 F 节通用规则）。

### GI-8 非前台 / 隐藏 PTY 宿主

- **目标**：隐藏与非活动宿主不得取得输入所有权（HO-2 进入条件）；其键盘让位结果不是实例的持久属性；切回旧实例时**不得恢复历史遮挡状态**，必须按当时的焦点、`scale` 与可用视口重新判定（对齐 D3；场景归属见 PLAN Phase 5"实例切换、隐藏宿主"，交接面见 C 表 F8 / F11）。
- **基线**：冻结文档 §4——所有宿主（包括隐藏和非活动宿主）都使用同一避让目标，新建宿主创建时立即应用当前值，即现状走"持续同步"。该基线与本目标不冲突，但**不被本文升格为唯一实现形态**（见 D3）；切换瞬间无历史遮挡的结论**尚未真机验证**。

### GI-9 诊断面板自身几何（R6）

- **目标**：所有要求居位在键盘与各 pan 状态下可读、可操作，或明确标记该居位不支持；不得因工具不可达而伪造产品 PASS。
- **基线**：快照未上报 `#viewport-debug-panel` 自身 rect；`panelLayoutFor()` 只使用 `vv.height`，无 `vv.offsetTop` 输入；顶部居位在外壳 −403px 平移时离屏，底部居位在键盘下可能被覆盖；既有 Node/Headless 测试未覆盖底部居位与非零 `vv.offsetTop`（VALIDATION"诊断面板自身问题"节）。工具层修正与产品几何修改必须分开提交（PLAN Phase 2 任务 2）；本段基线描述不构成产品实现授权。
- **Phase 2 矩阵口径（`937d91f` 的实现范围，不是真机 PASS）**：四角 `tl/tr/bl/br` 覆盖三档键盘 × 四档 pan（0、纵向 403、横向 44、横向 overscroll −120）；`free` 覆盖三档键盘 × 三档拖拽 × pan 0/纵向 403，另有横向与负 overscroll 边界用例。每格须满足 client rect 在屏显区域内，或显式 `unsupported` + 原因；Node 矩阵只证明纯函数与工具自报，不替代 iPadOS 真机 Capture / 截图。
- **单值不支持原因**：`unsupportedReason` 保持单个**首要原因**，双轴或落位同时不满足时按“纵向 → 横向 → 落位越界”的确定顺序取首因；本契约不要求多值 schema。首因之外不得反推其他轴已经充足，整格仍按 `unsupported` 处理。
- **工具干净停止（R6）**：`stop()` 后不得残留工具注册的 document / window / visualViewport 监听器或待执行 RAF、settle / retry / continuous 计时器，不得再产生新采集；重复 start/stop 不得重复注册。已开始的上传可自然结束，但不得续队或重试。Node 判据须使 `docListeners` 与 VV 监听器可观测为空、第二轮每个注册键仍恰有一个、停止后事件不新增帧；未被测试覆盖的计时器 / 在途上传不得由该测试单独宣称已验证。

## F. 验收口径（与 PLAN §6 真机矩阵衔接）

**通用判定规则**（PLAN §1.1 / §5 口径）：

- **PASS**：iPadOS 真机 Safari 上该条目全部 MUST 不变量在**连续、无缺口**的会话中成立，并含手动 Capture 与把诊断面板移离底边后的人眼截图；几何差值与截图同场保存。
- **FAIL**：任一 MUST 不变量在真机被观测不成立。持续 pan 与终端出屏为**停止型 FAIL**：停止实现并回到 D1，不追加阈值。
- **INCONCLUSIVE**：关键字段缺失、seq 缺口、场景未被覆盖、诊断面板不可达、或只有 Headless Chrome / CDP 结构证据。**缺证据不等于通过**；Headless Chrome 不替代真机键盘 / pan / zoom 证据（核心原则 §8 第 6 条）。
- **局部 PASS 不得覆盖整段**：`seq 367–486`（A 会话 `scale=1`）因 quick-keys 从未打开，该段单判 **INCONCLUSIVE**；`seq 88–99`（C 会话 quick-keys）只认证其几何与命中；C 全文件另有 8 个序列缺口，不得作为无缺口验收包。
- **证据完整性**：按冻结文档 §8 证据边界——缺 `probeVersion`、缺关键字段（`vv.height` / `app.bottom` / 根 `scrollTop` / `scrollingElementScrollTop` / `occlusion` / `controls` / `statusBar`）、缺结构字段、非 zoom 帧缺 `probe` 或 `probe.visualBottom`、seq 重复或有缺口，一律 **INCONCLUSIVE**。**戳记（`probeVersion`）必须匹配本次被测构建声明的值，不得在文档或判据里写死历史值**：现行冻结基线声明的戳记是 `p9-full-shell-session-avoidance-v1`（冻结文档 §8、现役 `evidence/verify-sop.mjs` 期望值）；`p8-full-shell-overlay-wheel-v1` 只出现在历史 A0-SOP（v3.1 / p8 时代历史执行 SOP）正文与其时代的历史会话中——**历史 SOP 与现役工具不同代**，回放历史 raw 时按该会话自身携带的戳记判定归属哪一代工具，不得混代比对，也不得以戳记不同反判历史会话造假。
- **探针 `ptyHosts[].visible` 的语义边界**：`visible` 只表示该宿主未被隐藏（未被打上隐藏类 / `display:none`），**不等于**它位于屏显区域内。C 会话 `seq 218`（`scroll` 过渡帧）宿主 `top=-363`、`bottom=-103` 而 `visible=true`；同一形态在稳定帧中反复出现（`settle` / `periodic` 共 52 帧，如 `seq 38–42`、`seq 85–87`；计入 `manual` 后 56 帧；另有 `keyboard-hint` 1 帧（`seq 264`，宿主底边同形态 −103），按稳定帧定义合计 **57 帧**）。**验收一律以 rect 与屏显区域 `[0, vv.height]` 比较为准，不得以 `visible=true` 判"可见"。**

**验收前置条件（工具依赖，不得绕过）**：

- 归属类条目（HO-1 判定与 HO-2 / HO-3 / HO-4）需要“归属类别 + 活动输入宿主类型 + 其可见 client rect”；`937d91f` 已增加这些 schema 字段，但字段存在不等于真机归属已被证明。F18 需要冻结 judge 可重放的连续测量、解锁事件与键盘顶边；F19 需要组合态标记或等价人工标注；D1 按 E 表补记的“顺序证据 + 同瞬间几何 / 归因 INCONCLUSIVE”口径执行；诊断面板须按 GI-9 的矩阵与真机门禁可达。前置工具未就绪或关键字段缺失时，相应条目一律记 **INCONCLUSIVE**，不得以 `ptyHosts[].visible`、角色启发式或派生标签推断归属、可见性或判 PASS。
- **派生会话提示不是第二真相源**：`keyboardSession.derivedState` 只是带 `derived:true` 的阅读提示，**不是验收权威**；会话验收权威仍是冻结 `makeKeyboardSessionJudge` 对探针测量字段的连续重放，再结合 `occlusion`、raw / VV 测量与 client rect 判定，且受头部重放保真度限定。`937d91f` 的五类 `unknown` 出口是：①applier mirror 未发布；②几何变化前不曾 active，不能推 geometry grace；③两帧间已有解锁留痕，不能推 recovering；④无 visualViewport；⑤从未进入与恢复锁不可区分。服务端强制 `derived:true`、并要求 `unknown` 携带非空原因，属于**形状门禁**，不证明推断内容正确，与“缺关键字段 / 无法判定一律 INCONCLUSIVE”一致：`unknown + 原因` 是显式不可得而非冒充已知；若该条目依赖会话状态且权威重放也无法判定，则该条目 INCONCLUSIVE。任何 `derivedState`（含 active / recovering / none）都不得单独产生产品 PASS / FAIL。
- **unlockTrace 的读者边界**：`937d91f` 可采 click / touchstart、tick 和同瞬间几何，但冻结 judge 不消费 `unlockTrace`，当前没有获授权的验收读者。它只是可采证 groundwork；GI-2 已登记集群及 F18 相关分歧在读者与判读流程另行授权前维持 **INCONCLUSIVE**，不得把“可采到”写成“已闭合”。
- **降级帧的可执行排他规则**：当 `probeReadFailed:true` 且 `probeReadFailedReason="probe-read-failed"` 时，除会话 / 帧封装、版本 / 采集原因和该失败标记外，**所有页面测量及派生字段一律不可读**。即使存储往返把客户端的 `null` 呈现为数值 0、空字符串或零值对象，也不得读取为事实，更不得据此判产品 PASS / FAIL；该帧参与的所有实质验收条目均为 **INCONCLUSIVE**。此规则优先于任何零值字段的表观形状。
- **事件环的当前传输宽容**：`geometryCountedOnly:true` 是采集器自报，不是服务端已逐条强制“环成员 = 决策集”的证明；`937d91f` 服务端词条仍允许几何类型，本轮明确保留该传输宽容。未来获授权的读者只能把 click / touchstart / focusin / focusout 条目用于相应判读，几何类型若出现在 entries 中则该 trace 判读 **INCONCLUSIVE**，不得当作决策事件。若要改成服务端硬拒绝，须另授权，不属于本契约修订。

**需用户确认项——语义互斥帧的传输处置（不改变 `937d91f` 现行行为）**：当前服务端对“已决定 ownership 仍带 unavailableReason”“supported 面板仍带 unsupportedReason”“unlockTrace.advisoryOnly 非 true”均以 400 拒绝。两条方向都不触及 PLAN §3 或 R1–R6：A. 维持语义错误 400，并把被拒绝帧视为证据缺口；B. **仲裁建议采用**：未知字段 / 非法类型等形状错误仍 400，上述语义矛盾或冗余则留存原帧、由 verifier 将相关判读记 INCONCLUSIVE，以免传输拒绝抹掉可复盘证据。B 以验收端排他规则已落实为前提，尤其不得因 `advisoryOnly:false` 而把 trace 升格为权威。**在用户拍板前维持 A；若选择 B，服务端、verifier 与测试改动均须转编码 / evidence 侧另授权。**
