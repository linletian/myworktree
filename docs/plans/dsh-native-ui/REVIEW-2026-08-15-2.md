## 1. 改动目的（回顾）

在 myworktree 中新增第 4 种受管实例类型 `dsh-web`：把 DeepSeek Harness 官方浏览器界面（`dsh web` = 无头 HTTP server + 内嵌 SPA）作为托管子进程内嵌进侧栏 iframe。核心设计：每实例独立 loopback origin 反代（SPA 的 API base 硬编码 `location.origin + '/api'`）、共享 `DSH_HOME` + restrict overlay 按 worktree 隔离工作区注册表、共享 sessions 池、越界只提醒不拦截、版本硬门 + L2 `--dump-config` 校验、缺失依赖三选对话框、远程模式强制 token 门。

### 2.3 修复引入的新行为（已核验，无新风险）

- **loopback 放行**：远程模式下仅"非 loopback 客户端"需过 token 门（`loopbackClient(r)` 按 `RemoteAddr` 判定）。与主 UI 的 loopback 信任模型一致：本机任何进程本就可读 `auth.json`，不算边界突破；注意 SSH 端口转发/本机代理也会被当作 loopback 放行——与"本机即信任"模型等价，已在 ARCHITECTURE §9 写明。
- **302 重定向只针对 GET/HEAD**（SPA 不知道 token，非导航请求不会带 token），且重定向在 token 校验通过之后、转发之前发生；token 始终经 `authq.StripToken` 剥离后才上游。顺序正确。
- **`wait()` 补 MarkFailed**：代理死亡触发实例拆除后，`MarkExited` 只记退出码，现在会在其后补 `MarkFailed(deathReason)`，前端能看到失败原因而非仅 stopped。
