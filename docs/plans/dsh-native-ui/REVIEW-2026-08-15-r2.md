## 四、复审新增观察（不在原 13 条里）

1. **`#1 + #3` 的修复带来了新约定，建议同步进 CHANGELOG/PLAN**：
   - install 两步确认（前端 UX + 服务端 mutex）—— 这条值得在 CHANGELOG 单列，否则下个 reviewer 看到按钮文案会迷惑
   - 代理 listener 死亡 fail-loud —— ARCHITECTURE §9 检查表第 5 条（"WS upgrade passthrough"）相关，可以再补一条 "listener death fail-loud" 进 checklist

2. **`TestProxyListenerDeathFailsLoud` 的 test fixture 值得看一眼**（`proxy_test.go:340-`）：
   - `fakePublisher` 注入 `MarkFailed` 钩子 + `marked` channel 验证回调（应该已读，留心 race）
   - 测试**仅覆盖** listener 死亡路径，**没覆盖** listener 在 TLS reload 后的恢复路径（AcceptLoop 重启语义）—— 但这是理论场景，不阻塞

3. **跨进程会话 bug 的 #2 缓解方向**（mtime 嗅探）作者拒绝，**认**。但**建议**：
   - 在 myworktree 的状态栏加一个**只读提示**（非 DOM 注入）："该 worktree 终端已跑过 dsh，会话可能处于活跃状态"—— 用户自己决定
   - 不需要 sniff，会话列表本身带 `mtime`，**已存在**（dsh 会话元数据），前端只读展示即可

4. **Token 302 跳转有个边界条件**值得留意：
   - 跳转后 iframe src 变成 token-free URL；如果用户**主动**回退到带 token 的 URL（点浏览器后退），会再被 302 一次 —— 体验上没问题
   - 但如果 `?token=` 含特殊字符（`+` / `&`）没 `encodeURIComponent` 处理过，`StripToken` 可能不识别 —— 浏览器会编码，前端 `_tokenizeIframeSrc` 也 `encodeURIComponent` 了，**两侧都覆盖**
   - 唯一死角：用户在地址栏**手敲**带特殊字符的 token（不走前端构造）—— 罕见，可接受
