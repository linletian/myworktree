## 六、分类缺口补登（issue #157，2026-11-11）

本节的三个类别**不在第一节的分类表里**，所以第一节那轮扫描「按当时的定义」是干净的——这不是那轮执行的疏漏，而是**标准本身的缺口**。本节只补登**定义与处理口径**，不保存任何原值，也不回溯既有提交。

| 新类别 | 匹配形态 | 为何算敏感 | 处理口径 |
| --- | --- | --- | --- |
| 第三方 agent 会话 / 实例标识 | `mvs_<32hex>` 全量、`mvs_<8hex>` 的**前缀式**引用、`mt-<6>` 实例 id | 第三方服务侧可据此关联、定位该用户的会话记录；是“他人平台的用户标识”，不是本机资源 | 等长替换为全零占位（`mvs_` 后跟同长度 `0`、`mt-000000`），保留长度与出现次数；前缀式与全量标识要保持同源关系 |
| systemd scope 标识 | `ptyxis-spawn-<uuid36>` 及 `ptyxis-spawn-<8hex>` 短式 | 机器身份信息；与 PID + 精确时间戳组合可锁定“某台机器某一秒的进程树” | 等长替换：UUID → `0000000N-0000-4000-8000-000000000000`，短式 → 同号 `0000000N`（保留“短式 = 全 UUID 首段”的关系与 A/B 区分） |
| 未发表的研究意图 | 检索式 / 会话标题 / 论文主题关键词 | 暴露的是**未发表的科研方向本身**，不是凭据；与私有仓库名叠加等于把私人工作区结构与研究主题一并公开 | 整段替换为 `[检索词已脱敏（N 组）]` / `[会话标题已脱敏（N 词）]`，保留组数 / 词数以免证据结构丢失 |

> 前缀式与截断式引用（如会话 id 只写前 8 位）**必须与全量形式一起扫**——只写 `\b<prefix>…<32hex>\b` 这类全量匹配会漏掉它们。2026-11-11 的实测里就漏了一处（已补）。

### 六-1 取证报告的落点规则

1. **取证 / 事故报告默认落在仓库外**（本仓约定：`~/mw-evidence/issue<NNN>/`）。仓库内的 `.archive/` 只作临时暂存，**不承担归档职责**——它被 `.gitignore` 覆盖，且随 worktree 一起删除，唯一副本会丢。
2. 同一份报告需要同时保留**原件**（不脱敏、仅本机）与**脱敏副本**（可引用），并附 `MANIFEST` 便于复算；脱敏脚本用模式匹配，脚本内不出现原值。
3. 报告进入任何跟踪文件（含 `docs/`）之前，**先**按第一节 + 本节清单脱敏，顺序不可颠倒。
4. 本规则**不新增**钩子、CI 扫描或新工具；`git add -A` 的入库入口由既有忽略规则关闭。
