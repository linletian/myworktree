## 二、B-1 / B-2 详解（已定案，保留推导链）

### 观察到的现象（OBSERVED）

iPhone 软键盘上（**2026-11-09 修正**：原记「iPad 同样复现」不成立——iPad 26键**无符号候选栏**、符号是 `comp=0` 直提交，该路径不可达；且**桥接关时终端连逗号都没有**，谈不上「不删**。真正的分界仍是「候选栏/composition 替换」，见 `T5-IPHONE-AB.md` §九之补 / §六 R4）：

- `，` 可**直接输入**（走 keydown 229 直提交）
- `。` 必须**先按逗号、再从候选栏里选句号**
- 选中的 `。` **不会自动删除已输入的 `,`** —— 终端最终留下 `,。`
- 一旦选中**成对**符号（如 `""`），**后续所有输入被打乱**：继续输入中文仍显示双引号，或输出不可预测的字符顺序

### 为何 iPad 四轮完全没暴露

本修复的 229 状态机**只在 `keydown` keyCode 229 时开窗**（`index.html:4150`）。

iPad 验过的全是「**点按直提交**」形态，窗口随每次敲击开闭：

```
keydown 229 → 插入 → keyup → flush 交付 → 关窗
```

iPhone 的候选栏形态不同——前一个字符已经交付并**关掉了窗口**，随后的替换由候选栏单独触发：

```
按 ',' → keydown 229 → 插入 → keyup → 交付 ',' → 关窗    ← 窗口已关
       ↓
从候选栏选 '。' → 只有一次 textarea 替换，无前置 229 keydown   ← 状态机不开窗
```

**这次替换没有任何窗口可以 diff。** B-1 与 B-2 都符合「textarea 被 IME 在 229 窗口**之外**改写」这同一形态。

### 候选机制（**2026-11-09 已判别；下列保留为判别前的原始假设**）

1. **窗口外改写，桥接按设计不可见** —— ✅ **成立**（机制 1）。候选栏点选**零 keydown**、`input.dt` 距上次 keydown **4368–4390ms**，且发生在桥接 `clear` 之后。
2. **成对符号使 textarea 进入游标居中态** —— ✅ **成立**（机制 2），且是 B-1 的直接机理：`baseline=…“你好”` / `current=…“你好1”` ⇒ `deliver delta="\x7f1”"`，野引号每敲一次冒一个。
3. **成对符号同时触发 composition 态并锁死 `iosImeComposing`** —— ❌ **未见证据**：`compositionend` 均正常闭合，后续 `keydown 229` 照常开窗并 `deliver`（26键腿 7/7 全角标点送达）。

### 判别所需的证据 → 已采集

三条判据全部落袋，**完整事件链原文、A/B 净化可见行、量化表见 `T5-IPHONE-AB.md` §三 / §四**；原始行见 `raw/iphone-on.capture.console.txt`、`raw/iphone-off.capture.console.txt`（校验 `raw/MANIFEST.md5`）。

采集方式已升级：**不再需要 Mac Web Inspector** —— 页面自带 `probe-v2` 采集器每 5s 回传服务端（`POST /api/ios-ime-capture`）。

## 四、已定案（不需再处理）

- **failsafe = 750ms，维持不下调。** 合并四轮 n=73 敲击，keydown→keyup max 246ms，>750ms 的敲击 0 次，余量恒为 3.0×；`via` 全程 `keyup-defer`，`failsafe` **零触发**。issue #124 原计划的 200–300ms 前提被实测证伪。
- **第 3 环假设**：47/50 成立，3 例 `dt:null` 全部由 branch B 正确抑制、无丢字（A-6 / R2-MINOR-1 正面作答）。
- **空格→。 等长替换**：delta = `\x7f。`，LCP 差分路径确认。
- **选字栏合成**：零 deliver、中间态拼音无泄漏。
- **死键路径**：CapsLock/Shift 的 keydown 有 probe 但非 229，状态机零介入。
- **硬件键盘对照组**：无回归；**229 是 IME 属性而非硬件属性**，软硬键盘对桥接不可区分。
- **桥接必要性区间（本轮新定案）**：**`keydown 229` + `insertText` + `comp=0`（直提交、无 composition）** ⇒ vendored xterm 完全不投递，**只有桥接能救**；composition 路径则由 xterm 自己在 `compositionend` 投递，桥接必须静默（本轮 25/19 次 `compositionupdate` **零泄漏**）。**分界线不是键盘布局，也不是设备，而是 composition 有没有参与。** 详见 `T5-IPHONE-AB.md` §五。
- **长按语义按设备/布局分叉（修正 §5.2）**：iPad 软键盘长按空格＝自动重复（`keyCode 32`）；**iPhone 长按空格＝光标移动**，不产生字符；iPad 长按数字＝弹字符选择器（默认中文「一」），**iPhone 长按数字就是该数字**。原 #4 收口判据作废，已改写。

详见 `plan.md` §3.2 / §5.1–§5.5 与 `DATA-COLLECTION.md` §四。
